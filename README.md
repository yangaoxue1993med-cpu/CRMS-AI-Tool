# CRMS 临床研究预算与时间线管理工具 V2.4.1

这是基于上传的 `CRMS_AI_Tool.py` V1.15 重构的 Streamlit 单文件应用。保留 示例项目 项目数据、四类预算模块和费用与时间线的规则匹配，提供中文工作台。无需外部 AI API 或数据库。

## V2.4.1修复：本地Streamlit兼容报错

**原因：** 上一版为保持折叠面板和页内标签状态，使用了较新Streamlit支持的`key`参数；部分本地安装版本的`st.expander`和`st.tabs`不接受该参数，启动时出现`unexpected keyword argument 'key'`。

**修复：** 运行时检测组件实际支持的参数。新版组件继续使用固定key；旧版组件采用其原生调用方式，不再传入不支持的key。预算、排期、中心与PI、入组记录以及中英文导出逻辑保持不变。兼容处理不捕获或掩盖其他组件错误。

**运行建议：** 可以先替换本次Python文件启动；推荐完整解压本次部署包，将入口文件和`requirements.txt`放在同一目录，并使用同一个Python解释器安装和运行。参考环境为Python 3.12。Windows用户可双击包内`START_CRMS.bat`，安装固定依赖并启动；该脚本需要Windows的`py`启动器和Python 3.12。如手动运行，在解压目录执行：

```bash
python -m pip install -r requirements.txt
python -m streamlit run CRMS_AI_Tool.py
```

停止旧服务后再启动新文件，避免仍运行下载目录里的旧版本。重新启动服务前，请先导出项目JSON备份当前填报数据。修复版页脚版本号为**2.4.1**。

官方参数参考：[Streamlit 1.50折叠面板](https://docs.streamlit.io/1.50.0/develop/api-reference/layout/st.expander)、[Streamlit 1.50标签页](https://docs.streamlit.io/1.50.0/develop/api-reference/layout/st.tabs)。

### 全中心月度入组折线图

- 项目概览汇总全部已登记中心。每个月一个累计点，计划为蓝色虚线、实际为青色实线，两条线均带圆点、用直线连接；横坐标显示月份。

- 分中心目标合计与项目设置不一致时提示差异；图表始终以已登记中心的计划为准。

已在浏览器复现旧版问题：从“启动阶段与检查清单”保存后，回到“中心与PI信息”，滚动位置回到顶部。新版做了以下处理：

## V2.1新增：中心启动与入组进度

本次在V2.0基础上新增两个独立页面，沿用原依赖，直接替换Python入口文件即可。旧V2项目JSON可直接载入，预算、日期、基线和实际支出保持原数据；首次使用时增加空的中心与入组清单，不编造真实中心或入组记录。

### 1. 中心启动进度

- “中心与PI信息”中登记中心编号、名称、PI姓名、PI联系方式和备注。可批量粘贴，也可按项目中心数先生成待填清单。
- “启动阶段与检查清单”中每个中心都有可拖动的阶段指针：未开始、研究合规、合同与财务、器械与临床资源、人员与数据、招募与中心激活。**拖动后立即保存到当前会话**。
- FPI准备检查逐项采用截图中的5类16项，可设为“待确认”“已完成”“不适用”。准备完成度按已完成/适用项计算。阶段指针与检查完成度独立，推动指针不会自动勾选检查，也不会生成实际入组数。
- 中心ID固定，修改名称或编号不影响历史入组关联。删除有入组记录的中心会被拦截，避免历史记录失去归属。

### 2. 入组进度

1. 在“分中心入组计划”填写各中心目标例数、计划首例与末例日期。可一键均分项目目标；不同中心可使用不同日期。
2. 在“实际入组填报”先选日期，再逐中心填写**截至该日累计入组**，不是当日新增。空白表示尚未报告，0表示明确报告尚无入组。
3. 同中心同日期再次保存会更新原快照，不会重复相加；历史表可补录、更正和删除。负数、未来实际日期、同日重复快照和累计数随时间下降会被拦截。
4. “曲线与导出”支持全研究合计、分中心对比和单中心。**计划为虚线，实际为实线**；同中心两条线使用相同颜色。
5. 曲线可下载SVG矢量图、可离线打开的交互HTML及CSV；图表右上角相机可导出高清PNG。全部中心、16项检查、累计快照和曲线数据同时加入Excel/CSV导出。
6. 项目JSON包含PI、联系方式、启动阶段、检查状态、分中心计划及全部入组历史，可保存后恢复。

### 曲线与联动口径

- 计划曲线采用“各中心起止日期内均匀分配”的可解释方法，允许预计累计数出现小数，末日达到整数目标；不是实际已入组人数。
- 实际曲线按累计报告日期阶梯连接，并停止在已报告日期。未报告的中心不会自动当作0；选定截止日之后的快照不计入本次曲线。
- 全研究合计实际线仅显示所有所选中心都有数据的共同报告区间。区间内沿用各中心最近已报累计数；中心首次明确报告0例，可据累计数不减少推知此前为0。若有中心未报告或无共同区间，暂不画合计实际线，可补同期快照或查看分中心曲线。
- 汇总表按各中心最近报告列示，显示报告日期和相对于该日期计划的差额；实际超目标会提示，仍保留真实数值。
- 分中心目标不会自动改写原预算。点击“用分中心计划同步项目人数与中心数”才会更新项目规模并重算人数/中心相关费用；同步会按当前排期维护方式更新项目时间线。
- 目前是中心级管理记录，不是患者级EDC，也不自动确认伦理、合规或中心激活有效性；清单状态由填报者确认。
- 数据仍保存在会话中。阶段指针虽自动保存到会话，刷新浏览器/服务重启前仍应导出项目JSON。

## 新增功能

- **实际支出台账**：关联费用ID、支付日期、币种、金额和备注；显示已付、剩余预算及超支提示。
- **预算/排期基线**：冻结预算和任务日期，显示后续预算差额、结束日期变化，并可在详细甘特图叠加基线。
- **执行进度**：任务负责人、完成度和实际完成日期；前置ID检查循环及先后冲突，任务到期未登记完成时提示。
- **入组情景测算**：保守/参考/积极速率，比较入组曲线、预计工期和相关费用；不会改动当前项目。
- **访视费用分期**：按入组月份＋访视间隔分配费用，显示首例到末例的访视窗口。
- **付款滞后**：费用可选择阶段均摊、开始/结束一次性，并逐行填写付款滞后月数。
- **可选风险储备**：默认0%，启用后单独列示，不与已承诺费用混淆。
- **输入与导出校验**：日期、负数、无穷值、失访人数、ID、依赖循环、财季和百分比检查；CSV/Excel自由文本按纯文本导出。

## 推荐使用顺序

1. 在侧栏打开“新建项目模板”，选择示例项目或通用，然后点击“新建并载入模板”。已有项目先导出JSON。
2. “项目设置”填写规模、随访月数、入组速率和汇率；点击“保存项目设置”。
3. “预算编制”填写各行费用。小时计费的数量填工时；FTE计费先选清楚项目/月/年的单价口径。
4. 访视费需要单独计费时启用。示例项目原Site Cost已含随访费用，默认不再叠加。
5. “时间线管理”核对或手工改期，保存后采用“手工维护”；依赖冲突会提示，由用户决定是否允许任务滚动开展。
6. “现金流计划”选择分配方式，核对峰值季度；自定义占比须合计100%，可显式点击归一化。
7. 保存基线，在执行中登记实际支付；按需要导出Excel、CSV和JSON。

**表格内输入后须点击该表单的保存按钮。切换页面前应先保存。**

- 示例项目模板日期固定，修改入组速率只影响情景测算；在模板排期方式下改变基准日会整体平移日期。原始季度模式保持原季度资金计划，若需随日期重新分摊，请切换“智能匹配时间线”。
- 项目财季采用月份口径，不能替代公司正式逐周财务日历。默认6月起始：FY27Q1=2026年6–8月；2026年2月历史例外单独控制。
- 项目月数按含首尾日期的日历时长计算，整月为1个月，部分月按相邻月长度折算。月度现金流均摊按覆盖的日历月份分配，不按每日权重。
- 管理费基数为研究中心直接费用＋启用的访视费用；Site计税是否包含管理费可选；Vendor税仅基于供应商直接费用。示例项目总额录入默认不再叠加税费或管理费。
- 完成随访人数=计划入组−预估失访。仅明确选择该计费人群的费用减去失访；不假设失访者从未接受手术、筛选或发生任何访视。
- 入组模型假设中心按月线性启动、单中心速率恒定，允许小数作为期望例数。情景中按模型月数比例调整现有入组窗口，再顺延后续任务；固定总额费用不自动涨价。
- “智能规则”保留原程序费用匹配规则；找不到关联阶段时显式提示，并按全项目周期摊分。付款滞后、晚期访视或自定义季度可能产生项目任务周期外现金流，系统会提示。
- 外币实际支出按当前规划汇率重估；未实现逐笔历史汇率或会计账务。“剩余预算”是预算减去已支付，不是完工尚需成本预测。
- **数据保存在当前会话中，未接入数据库**。刷新浏览器、会话失效或服务重启可能清空当前填报数据；请下载项目JSON备份，再用“载入文件”恢复。JSON包含预算、日期、基线和实际支出。V1无项目JSON导出格式，因此不支持导入任意旧格式文件。
- 当前版本不包含多用户权限、共享编辑、审批流、邮件提醒或数据库；提醒为打开应用时的页面检查。后续正式上线多人使用时，可在此基础上接入统一存储和身份系统。
